# Joan of Arc : Banner of Orleans

A 2D side-scrolling action game built with the **iGraphics** framework in
**C++ / Visual Studio 2013**.

Team: Obonty Orin Anta, Sidana Tahrin, Tahsin Saba, Iffat Jahan

## How to run

1. Open `demo\demo.sln` in Visual Studio 2013.
2. Press **F5**.

Run it from Visual Studio, not by double-clicking the exe — the game loads its
art and sound with paths relative to the working directory, which VS sets to the
project folder.

## Controls

| Key | Action |
|---|---|
| `A` `D` or `←` `→` | move |
| `SPACE` or `W` | jump |
| `J` or left mouse | sword |
| `K` or right mouse | bow (from stage 2) |
| `Q` | Sacred Mending — heal self and nearby companions (stage 2) |
| `E` | Oriflamme Call — summon companions (stage 3) |
| `R` | Banner of War — strike every enemy near you (stage 4) |
| `P` or `ESC` | pause |
| `M` | music on / off |

## The campaign

Three missions: **The Siege of Orleans**, **The March to Patay**, **The Enemy
Commander**. Fight to the banner at the end of each field; the last one ends
with the commander himself.

Joan grows through four stages (the *Path of the Maid*). After mission 1 you
choose **the Blade** (heavier melee) or **the Bow** (ranged, faster). Each
stage raises her health and unlocks an ability, and the commander's arrival
promotes her to stage 4.

Enemy ranks counter each other:

| Rank | Notes |
|---|---|
| Brute | balanced, no weakness |
| Pikeman | heavy armour, but arrows do double damage |
| Crossbow | shoots from range, dies fast to the sword |
| The Commander | boss, three phases, gets faster as it weakens |

## Architecture in one paragraph

`iMain.cpp` only dispatches. The framework calls `iDraw()` continuously,
`fixedUpdate()` every 8 ms for input, and two `iSetTimer` callbacks — one at
20 ms for simulation and one at 120 ms for animation. `gameState` decides which
screen draws and which handler reads the keyboard, so adding a screen means
adding one enum value and two functions. During play the 20 ms tick runs
`updateGame()`, which updates the player, the units, the projectiles and the
effects, then resolves **all** collisions in `Combat.hpp`, then moves the
camera. Nothing in the drawing path ever changes game state.

The iGraphics framework files are never modified. Where the framework was not
enough, the game adds its own code beside it: `Assets.hpp` draws sprites with
real alpha blending and horizontal flipping (`iShowImage` can do neither), and
`Audio.hpp` adds sound, which iGraphics does not have at all.

## Rebuilding the art

Only needed if the source images change:

```bash
pip install pillow
python tools/prepare_assets.py
```

See `tools/README_ASSETS.md`. The script cuts the background out of the source
art, fits each sprite into a power-of-two canvas and regenerates
`AssetList.hpp`. Then rebuild in Visual Studio.
